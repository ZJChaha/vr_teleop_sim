# 04 · 相机

## 1. 两种配置方式（都不改 XML）

| 方式 | 场景 | 字段 |
|---|---|---|
| **内存注入** | 模型里**没有**这个相机（比如想加一路"俯视"） | `extra_cameras` |
| **绝对覆盖** | 模型里有，但想换位置/朝向/FOV | `camera_overrides` |

两者都在 `robot_profile.py` 里，格式相同：

```python
extra_cameras = {
    "cam_top": dict(pos=(0.062, 0.0, 1.255),
                    quat=(0.6869, 0.1679, -0.1679, -0.6869),
                    fovy=46.5),
}
camera_overrides = {
    "cam_scene": dict(pos=(-0.18, 0.66, 0.97),
                      quat=(0.3738, 0.1955, -0.4202, -0.8034),
                      fovy=52.0),
}
```

* `pos` 单位米，**世界坐标**
* `quat` 是 MuJoCo 的 `(w, x, y, z)`，**相机光轴 = 自身 -z**
* `fovy` 单位度（**垂直**视场角）

> **为什么要"只改内存"**：模型文件是共享的（可能别的脚本/别人的仓库也在用），
> 改 XML 容易冲突；而且内存覆盖天然可回滚 —— 把字典置 `{}` 就回到 XML 原值。

注入的实现见 `camview.load_model_with_cams()`：用 `MjSpec` 在**编译前**往
`worldbody` 加一个 `<camera>`，再 `spec.compile()`。实测与 `from_xml_path`
编译结果**除 `ncam` 外完全一致**（同一 qpos 步进后 `xpos` 差 0.0），所以不会
影响任何物理。

## 2. 每一路都能单独打开/关闭

`CameraSpec` 有**两个独立开关**：

```python
cameras=[
    CameraSpec("全局相机",     "cam_scene", "observation.images.scene"),
    CameraSpec("腕部相机",     "wrist",     "observation.images.wrist"),
    CameraSpec("全局俯视相机", "cam_top",   "observation.images.top"),
]
```

| 参数 | 作用 | 影响 |
|---|---|---|
| `preview=True/False` | 是否开预览窗口 | 只影响你能不能看见，**不影响数据** |
| `record=True/False` | 是否写进数据集 | 每一路 = 多渲一遍 + 多一轨 mp4 |

三个典型组合：

```python
# ① 只看不录（调机位时）
CameraSpec("全局相机", "cam_scene", "observation.images.scene", preview=True,  record=False)

# ② 录但不看（正式采集，省 GPU）
CameraSpec("全局相机", "cam_scene", "observation.images.scene", preview=False, record=True)

# ③ 完全不用（换成自己的相机后，把参考实现的某一路关掉）
CameraSpec("全局相机", "cam_scene", "observation.images.scene", preview=False, record=False)
```

`tools/check_profile.py` 会打印当前的实际组合，例如：

```
✅ 相机开关 — 预览 3 路 ['cam_scene','wrist','cam_top']｜录制 2 路 ['wrist','cam_top']
```

> ⚠️ 改 `record` 等于改数据集特征集 ⇒ 不能往旧目录续写（见 docs/05「一致性约束」）。

## 3. 给视频数据集选哪几路

**不需要三路全录。** 每一路录制都让文件体积和渲染开销成倍增长，
而 VLA 通常只需要"手边细节 + 一个全局上下文"。

推荐配置是 **两路**：

```
腕部相机（wrist）  +  侧面全局（cam_scene）  或  俯视全局（cam_top）  二选一
```

| | 侧面全局 `cam_scene` | 俯视全局 `cam_top` |
|---|---|---|
| 机位 | 斜侧上方（像"看自己手臂"） | 基座上方俯视，桌面边与画面平行 |
| 看得到 | **机械臂整条 + 目标 + 周围空间** | **桌面布局、物体之间的相对位置** |
| 看不到 | 桌面上被臂挡住的角落 | 机械臂的姿态（臂基本是俯视投影） |
| 适合 | 需要知道"臂在哪、怎么动"的任务 | 需要知道"东西摆在哪、堆叠关系"的任务 |
| 代价 | 臂会挡一部分桌面 | 看不出垂直于桌面的高度变化（深度感弱） |

怎么选：

* 任务强调**抓取/放置的相对位置**（堆叠、码放、按顺序搬运）→ **俯视全局**
* 任务强调**长距离移动、绕开障碍、姿态调整** → **侧面全局**
* 不确定时：先两路都录 **20~30 集**，各自训一版（或者看哪一路里目标更清楚），
  再把用不上的那一路关掉。别一开始就三路全开——体积翻 1.5 倍、帧率还更容易掉。

体积参考（实测，640×480 / 50fps / H.264）：

| 视角 | 体积 |
|---|---|
| 侧面全局 `cam_scene` | ≈ 49 KB/s |
| 腕部 `wrist` | ≈ 100 KB/s（运动更剧烈，码率高） |
| 俯视全局 `cam_top` | 与 `cam_scene` 同量级 |

以 294 集 / 86824 帧（1736 秒）的两路真实数据集为例：**258.6 MB**。

```
两路 30 秒的集 ≈ 4.5 MB
三路 30 秒的集 ≈ 6 MB      （多出来的那路 ≈ 1.5 MB/集）
```

单集看着差别不大，但 300 集就是 **1.3 GB vs 1.8 GB**；而且多一路渲染更容易掉帧到 37Hz
（见第 5 节）。

怎么切：

```python
# 要俯视全局（关掉侧面全局的录制，但留着预览方便观察）
CameraSpec("全局相机",     "cam_scene", "observation.images.scene", preview=True,  record=False),
CameraSpec("腕部相机",     "wrist",     "observation.images.wrist", preview=True,  record=True),
CameraSpec("全局俯视相机", "cam_top",   "observation.images.top",   preview=True,  record=True),
```

反过来想要侧面全局，就把两行的 `record` 对调即可。

> 换了机器人之后，三路相机的机位**都要重调**（相机与机械臂几何强相关），
> 调机位期间可以先用 `preview=True, record=False` 看画面，定好再打开录制。

## 4. 三路相机分别干什么

| 名称 | 挂在哪 | 作用 |
|---|---|---|
| `cam_scene` | 世界固定（斜侧上方） | 全局：看整条臂 + 桌面 + 所有物体 |
| `wrist` | 挂在腕部连杆 | 近景：看夹爪与目标的相对位置（抓取精度靠它） |
| `cam_top` | 世界固定（基座上方俯视） | 俯视：看桌面布局与堆叠关系（参考实现用内存注入） |

对 VLA 训练来说：**腕部相机决定"抓得准不准"，全局相机决定"知不知道自己在大局的哪"**。
只给一路通常不够。

## 5. 性能：三路 640×480 很难压进 50Hz

实测（AMD RX 5500 XT / Mesa radeonsi，640×480）：

```
mjr_render 默认会给"阴影"和"反射"各多渲一遍整个场景
  单帧 6.12 ms（原样）
       4.06 ms（关 shadow）
       1.81 ms（再关 reflection）   ← 降 3.4 倍
       1.62 ms（再预分配 out 缓冲）
```

三路相机 → 18.4 ms/帧，逼近 20 ms 的 50Hz 预算，实测只能到 **37 Hz**。
把 `render_off=("shadow", "reflection")` 打开后 → **50 Hz，零慢拍**。

```python
# robot_profile.py
render_off: Tuple[str, ...] = ("shadow", "reflection")
```

代价：少一层地面反光、少了物体投在桌面上的阴影。实测三个视角上肉眼差别很小，
但**如果你的任务依赖阴影（比如判断高度），就把它置 `()` 并降低分辨率或帧率**。

> ⚠️ 这个设置**同时作用于预览窗口和录数据**（两边共用同一套参数），
> 保证"你看到的"就是"录进去的"。

## 6. 挑机位的方法（比"看着调"快得多）

### 4.1 先定"视角语义"，再定参数

参考实现踩过两次方向错误，先想清楚这一条能省很多时间：

| 想要的画面 | 相机应该在哪 |
|---|---|
| "像人看自己手臂"（第三人称） | 在臂的**侧方**（+y 侧），光轴大致垂直手臂平面 |
| 俯视看桌面布局 | 基座/工作区**正上方**，光轴接近竖直 |
| 第一人称 | 挂在腕部（`wrist`） |

> 反例："从臂正后方朝前看" —— 近端连杆会变成巨大前景，挡住桌面。

### 4.2 三个必须遵守的做法

1. **用真实初始姿态渲染**。相机是给人看的，人的姿态就是 `home_qpos`；
   拿别的姿态挑出来的机位，真跑起来会不一样。
2. **对比图不要压扁**。640×480 拉成 640×360（16:9）会纵向失真 25%，
   在压扁的图上是判断不出"俯角对不对"的。
3. **量指标，不只靠眼睛**。遮挡、出画、目标像素面积都可以自动量：

```python
# 用分割渲染量"机械臂挡住目标多少"
r.enable_segmentation_rendering()          # ★ 必须先调，否则拿到的是红色通道
r.update_scene(d, camera=cid); seg = r.render()[:, :, 0]
# seg == geom_id → 哪些像素是臂、哪些是目标、哪些是桌面
```

参考实现就是靠这个把"臂遮挡最坏 94% → 23.6%"，并把最小目标轮廓从 329px
提到 951px。

### 4.3 一个可复用的搜索流程

```python
# 对候选机位 (pos, quat, fovy)：
#   ① 把工作区 8 个角点投影到 640x480，要求全在画面内且离边 ≥ 15px
#   ② 渲染 home 姿态，量目标色块像素数（越大越好）
#   ③ 量臂在画面边缘的像素（贴边说明要出画了）
#   ④ 排序：像素大 + 不出画 + 遮挡少
```

参考实现用这套流程定出了 `cam_top`：**相机在基座上方 11cm、高 1.26m、
俯角 72.5°、fovy 46.5°**，桌面远边与画面边缘**完全平行（0.00°）**，
目标像素是原方案的 3.7 倍。

## 7. 相机与"平行/方正"

如果你希望**桌子的边与画面边框平行**，几何上有两条路：

| 想要 | 条件 |
|---|---|
| 只有**顶边（远边）**平行 | 光轴**不左右偏**即可（相机与瞄准点同 y、无 roll） |
| **四条边**都平行 | 光轴必须**垂直向下**（正交俯视），且相机要挪到桌面中心上方 |

参考实现选了前者：相机留在基座正上方（俯角 72.5°），把 y 归零，
远边就精确水平；四条边全平需要相机离开基座，和"基座正上方"的要求冲突。

> 量化方法：把桌子四角投影到图像，算四条边与画面水平轴的夹角，
> 0° / 90° 为完全平行。参考实现归零前是 1.1°，归零后 0.00°。

## 8. 相机窗口摆放

```python
# server.py
CAMVIEW_POS = ["+1904+80", "+1904+620", "+1256+80", "+1256+620"]   # 2×2
```

TK 的 `+x+y` 是**左上角坐标**。640×480 的窗口带标题栏约 520px 高，
三个竖排在 1440p 屏幕上放不下，所以用 2×2。

VR_TELEOP_CAMVIEW=0 ./run.sh     # 只录数据，不显示预览窗口
